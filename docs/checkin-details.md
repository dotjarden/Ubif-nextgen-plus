# Extra Details

Always enabled on `/check-in`. The heading is “Extra Details,” positioned immediately above the native Additional Details block with Portal colors, inherited typography and an unboxed two-column layout. Standard and Samsung diagnosis forms receive eight extra fields: Model, Color and Device Issue text boxes; FMIP off/on; Accessories Offered and Services Offered yes/no; ETA and Price Est text boxes. All eight fields are required before the native diagnosis Continue action or containing form submission can proceed. Missing or whitespace-only entries are listed and focused; ETA accepts “unsure.” The guard also blocks continuation during a battery update or when Extra Details cannot be applied to native notes. Choices start unselected. ETA accepts free text, including “unsure”; the custom ETA and price do not change Portal’s native repair estimate or billing.

The MAIN-world script `extension/checkin.js` uses the current mounted native Notes textarea’s own React `onChange` handler. It appends a plain “Extra Details:” section to the existing notes, with no extension branding or closing marker. Older branded sections hydrate normally and are cleaned up when the diagnosis form loads. Portal owns the save, diagnosis rules and work order binding. Completing normal check-in saves the combined text to the order’s `additionalDetails`, alongside all native diagnosis fields. It is visible in the native notes field before submission. No separate API writes, extension storage, or save retries occur.

Contracts checked against the public `https://portal.ubreakifix.net/assets/ubif-check-in.js` bundle on October 12, 2026:

- Standard Notes uses `data-testid="additional-details-note"`; Samsung uses `data-testid="DeviceDiagSubIssues_Notes"`. Both callbacks consume `event.target.value` and allow 2,000 characters.
- The diagnosis update is `PUT /api/checkin/workorder`; its body includes `workorderId`, `customerDeviceId`, `deviceIssues` or `deviceIssuesWithSubIssues`, `deviceDiagNotes`, and `additionalDetails`.
- No custom fields are added to native diagnosis enums. Custom details remain labeled supplemental notes.

Changing a field replaces the custom block while preserving other notes. Reopening diagnosis reads the block from Portal’s notes state. Removing the native textarea disposes the controls; a new form hydrates only from its own notes. Missing handlers, disabled/read-only notes, ambiguous forms and other routes do not write. Entries exceeding the combined Notes limit are rejected with visible feedback and the last accepted value is restored.

Automated fixtures cover both forms, all eight fields, current React handlers, notes preservation, reopening, fresh forms, limits, disabled/unsupported forms, routes, ambiguity and handler failures. An authenticated end-to-end check-in remains outstanding; no production order was created or modified during implementation.

The “Battery not working” button appears directly below the diagnosis heading (above the native categories when a heading is unavailable). The Quick diagnosis label and explanatory paragraph have been removed. The button changes only native diagnosis selections and required native test-reason text. It never reads, fills, clears or validates Extra Details, nor changes its saved section.

The shortcut reads current standard/Samsung accordion props, including collapsed children. It continues past partial inner renders (such as Hardware alone) to find the full sibling category list, preferring complete reason props when views tie. The adapter resolves the textarea and its ancestor path from React’s committed root rather than trusting the DOM’s retained fiber pointer; reused return pointers can otherwise expose old unchecked props and stop the action after Hardware. It clears selected native issues through enabled callbacks, then selects each category’s “Can’t test” option. Each selection is confirmed before proceeding. Standard categories must expose their required reason textarea; the shortcut opens collapsed sections if necessary and waits for the notes to mount. It supplies “Unable to test because the battery is not working.” when reason text is empty or too short, preserving existing text. Already selected Can’t test options stay selected. Disabled/ambiguous actions stop the update; progress and partial failures identify what needs review. It verifies all categories at completion and never saves the order or overrides Portal’s disabled Continue state. IQC/power controls remain native.

The independent Extra Details guard still requires all eight fields. A complete section already present in native Notes can proceed without another write, including when Portal renders those notes read-only.
